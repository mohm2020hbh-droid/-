# Shape Jump — Game Design Specification

> الإصدار: v0.1 (Prototype) · المنصة: Android أولًا (Mobile, Landscape) · المحرك: Godot 4.7
> الاسم "Shape Jump" اسم عمل مأخوذ من الصورة المرجعية، ويمكن تغييره لاحقًا.

---

## 0. الفكرة في جملة واحدة

**نواة هندسية مضيئة تعبر مدينة هندسية ميتة وحمراء. تجري وحدها. أنت تقرر متى تقفز فقط.**

لعبة 2D Arcade Runner بلمسة واحدة. المتعة لا تأتي من السرعة بل من **قراءة المسار واختيار لحظة القفز**.

---

## 1. تحليل المتطلبات → قرارات التصميم

| المتطلب | القرار التصميمي |
|---|---|
| تحكم بلمسة واحدة، لا أزرار حركة ولا أسلحة | لمسة في أي مكان = قفزة. لا شيء آخر. الضغط المطوّل لا يفعل شيئًا. |
| الحركة للأمام تلقائية | سرعة جري ثابتة لكل مستوى (قابلة للضبط من بيانات المستوى). |
| لا Double Jump | القفز ممكن فقط من الأرض (أو خلال نافذة Coyote قصيرة جدًا بعد مغادرة الحافة). |
| Jump Height ثابتة وقابلة للضبط | القفزة تُعرَّف بـ **ارتفاع** و**زمن الوصول للقمة**، والجاذبية وسرعة القفز تُشتق منهما رياضيًا. لا قفزة متغيرة حسب مدة الضغط. |
| الدوران لا يؤثر على الـcollision | صندوق التصادم لا يدور أبدًا. الدوران موجود فقط في طبقة الرسم (Visual). |
| عوائق غير منسوخة من runners قديمة وتعتمد على التوقيت والقراءة | كل عنصر يطرح **سؤالًا واحدًا واضحًا** على اللاعب (انظر §7). العناصر المتحركة مربوطة بساعة المستوى فتكون قابلة للحفظ والتعلم. |
| مستويات غير عشوائية ونظام قابل للتوسع | المستوى = سلسلة **Beats** مصممة يدويًا من عناصر جاهزة على Grid بحجم 64px. |
| صعوبة متدرجة لا تعتمد على السرعة فقط | 6 مفاتيح صعوبة مستقلة (§8.4). |
| Mobile First وUI لا تغطي اللعب | HUD في الزوايا العليا فقط، بحجم صغير، مع احترام الـSafe Area. |
| هوية بصرية داكنة Neon سينمائية | أسود + أحمر Neon واحد رئيسي + أبيض ساخن للاعب فقط. طبقات Parallax للعمق. |

### خارج نطاق المرحلة الأولى (عمدًا)
قائمة رئيسية، اختيار مستويات، متجر، إنجازات، إعدادات متقدمة، Localization، Leaderboards، Ads، موسيقى خلفية، مستويات إضافية. النظام مصمم لاستقبالها لاحقًا دون إعادة كتابة.

## 2. الركائز (Design Pillars)

1. **لمسة واحدة، قرار واحد** — كل ثانية في اللعبة تطرح سؤالًا: "أقفز الآن أم لا؟".
2. **اقرأ المسار** — كل خطر مرئي ومقروء قبل وصوله بوقت كافٍ. لا مفاجآت خارج الشاشة.
3. **دقة عادلة** — إذا مات اللاعب يجب أن يعرف لماذا، ويشعر أنه كان يستطيع النجاة. Hitboxes متسامحة، ولا عشوائية.
4. **Minimal لكن Cinematic** — أشكال قليلة، إضاءة قوية، عمق بالطبقات، Feedback واضح لكل حدث.

## 3. Core Gameplay Loop

```
RUN → JUMP → AVOID → LAND → CONTINUE
 ↑                              │
 └──────────────────────────────┘
```

| المستوى الزمني | الحلقة |
|---|---|
| **Micro** (1–2 ثانية) | أرى عائقًا → أختار لحظة القفز → أهبط → Feedback (Particles + صوت + Squash) |
| **Meso** (10–15 ثانية) | Beat واحد يعلّم فكرة → Checkpoint → Beat أصعب يطوّرها |
| **Macro** (دقيقة تقريبًا) | إنهاء المستوى → Score + Shards → محاولة كسر أفضل نتيجة |

**لحظة "مرة ثانية":** الموت → تحطم النواة → بعد أقل من ثانية تعود عند آخر Checkpoint وتجري مجددًا. لا شاشات، لا انتظار.

## 4. التحكم (Controls)

| الإدخال | النتيجة |
|---|---|
| لمسة في أي مكان من الشاشة (بأي إصبع، حتى لو كان إصبع آخر مستقرًا على الشاشة) | قفزة (إن كان مسموحًا) |
| لمسة على زر Pause | إيقاف مؤقت (لا تسبب قفزة) |
| (للتطوير على الكمبيوتر) Space / ↑ / W / زر الماوس | قفزة |

### أدوات عدالة غير مرئية (ليست ميكانيكيات جديدة)
- **Jump Buffer (0.12s):** إذا ضغط اللاعب قبل الهبوط بلحظة، تُنفَّذ القفزة لحظة الهبوط. يمنع شعور "ضغطت ولم يقفز".
- **Coyote Time (0.08s):** يمكن القفز بعد مغادرة الحافة بجزء صغير من الثانية. يمنع شعور "كنت على الحافة!".
- **Ledge Assist (10px):** إذا اصطدم اللاعب بحافة منصة وكان أسفلها بأقل من 10px — أثناء الجري أو أثناء السقوط على زاويتها — يُرفع فوقها بدل أن يموت.

## 5. الشخصية: "النواة" (The Core)

### الشكل
مكعب مسطح مرسوم كإسقاط **Tesseract** (مكعب رباعي الأبعاد):
- مربع خارجي داكن بحواف Neon حمراء.
- مربع داخلي بلون **أبيض ساخن** — أكثر نقطة سطوعًا في الشاشة كلها، لذلك يُميَّز اللاعب فورًا.
- أربعة خطوط تصل زوايا المربعين (إيحاء العمق الرباعي).
- المربع الداخلي **يتأخر قليلًا عن الحركة** (Inertia) ويدور ببطء عكس الجسم → إحساس بأن داخله بُعدًا آخر.

### الحالات (Animation States) — كلها هندسية وإجرائية (Procedural)

| الحالة | ماذا يحدث بصريًا |
|---|---|
| **Idle** | النواة الداخلية "تتنفس" (نبض حجم)، توهج الحواف ينبض ببطء. تظهر قبل أول لمسة. |
| **Run** | النواة الداخلية تدور باستمرار كجيروسكوب، شرارات صغيرة من الحافة الخلفية السفلية، ذيل ضوئي خفيف. |
| **Jump** | Stretch عمودي لحظي، دفقة Particles من الأسفل، الجسم يبدأ بالدوران (نصف دورة لكل قفزة كاملة). |
| **Fall** | الدوران مستمر، النواة الداخلية تنزاح للأعلى (قصور ذاتي) حسب سرعة السقوط. |
| **Land** | Squash سريع ثم ارتداد مرن، الدوران ينطبق على أقرب زاوية 90°، غبار ضوئي على الجانبين. |
| **Death** | الجسم يختفي، يتحطم لشظايا مربعة، حلقة ضوء تتوسع، اهتزاز كاميرا خفيف جدًا. |

**قاعدة ذهبية:** صندوق التصادم (48×48) ثابت دائمًا وغير دوّار. كل ما سبق Visual فقط.

## 6. مواصفات الفيزياء (Physics Spec)

وحدة القياس: 1 Tile = 64px. المحور Y للأسفل (Godot).

| المعامل | القيمة المبدئية | ملاحظة |
|---|---|---|
| حجم جسم اللاعب | 48 × 48 px | 0.75 Tile |
| Hurtbox (منطقة الموت) | 36 × 36 px | أصغر من الجسم = تسامح 6px من كل جهة |
| سرعة الجري | 520 px/s (≈ 8.1 tiles/s) | قابلة للضرب بمعامل من بيانات المستوى |
| ارتفاع القفزة | 150 px (≈ 2.34 tiles) | يتخطى عائقًا بارتفاع 2 Tiles بهامش 22px |
| زمن الوصول للقمة | 0.36 s | |
| جاذبية الصعود (مشتقة) | g = 2h / t² ≈ 2315 px/s² | |
| سرعة القفز (مشتقة) | v = 2h / t ≈ 833 px/s | |
| مضاعف جاذبية السقوط | 1.3 | سقوط أسرع قليلًا = إحساس أثقل وأدق |
| أقصى سرعة سقوط | 1400 px/s | |
| Floor Snap | 12 px | يمنع "الطيران" عن المنصات النازلة |
| معدل الفيزياء | 60 tick/s ثابت + Physics Interpolation | منطق ثابت، رسم ناعم على شاشات 90/120Hz |

### مقاييس القفزة المشتقة (أساس تصميم المستويات)
- زمن القفزة على أرض مستوية ≈ **0.68s**.
- المسافة الأفقية للقفزة ≈ **351px ≈ 5.5 tiles**.
- أقصى فجوة نظرية ≈ 6 tiles. **قاعدة التصميم:** فجوة مريحة ≤ 3 tiles، صعبة 4–5 tiles، ممنوع > 5.
- أعلى عتبة يمكن الصعود عليها: **2 tiles**.
- الفجوات حتى **1 tile** تُعبر بالجري دون قفز (الجسم أعرض من أن يسقط فيها)؛ فجوة 2 tiles بدون قفز = موت. (مُختبر)

### قواعد التصادم
- **الأرض:** Ground Detection عبر `CharacterBody2D.is_on_floor()` بعد كل `move_and_slide()`.
- **الاصطدام بجدار من الأمام:** Ledge Assist أولًا، وإن فشل → **موت**. (الجري التلقائي بدون هذه القاعدة يسبب Softlock: اللاعب يدفع الجدار للأبد.)
- **الاصطدام بالسقف أثناء القفز:** تتوقف الحركة للأعلى فقط (ليس موتًا).
- **الأخطار:** تلامس Hurtbox مع Hitbox الخطر → موت. Hitbox الخطر أصغر من رسمه.
- **السقوط:** تجاوز خط `kill_y` للمستوى → موت.
- **السحق:** إذا ضغطت منصة متحركة اللاعب في سقف (أرضية وسقف معًا) → موت، بدل أن يخترق إحداهما.
- **المنصات المتحركة:** تحمل اللاعب **عموديًا فقط**؛ سرعة الجري الأفقية لا تتغير أبدًا، ولا يرث اللاعب سرعة المنصة عند القفز → ارتفاع القفزة ثابت دائمًا.

### الحتمية (Determinism): المستوى كمقطوعة موسيقية
- كل العناصر المتحركة (منصات، مناشير، منصات تختفي) موقعها **دالة في ساعة المستوى** `f(t)` وليست تراكمية.
- سرعة الجري الأفقية ثابتة دائمًا (حتى فوق المنصات المتحركة)، لذلك **كل موضع x يقابل لحظة زمنية واحدة ثابتة**: `t = (x − x_spawn) / speed`.
- النتيجة: القفز يغيّر الارتفاع فقط، أما توقيت كل عائق عند وصولك إليه فثابت في كل محاولة → المستوى قابل للتعلم والحفظ، والمصمم يضبط أطوار العناصر حسابيًا من موقعها.
- عند العودة إلى Checkpoint تُعاد الساعة إلى لحظة مرور مركز اللاعب به بالضبط، فيجد اللاعب **نفس التوقيتات تمامًا**.

## 7. عناصر المستوى (Element Catalog)

### لغة الأشكال (Shape Language)
| الشكل | المعنى |
|---|---|
| مستطيل / مربع بحافة Neon علوية | آمن — يمكن الوقوف عليه |
| مثلث / أسنان حادة | خطر — موت عند اللمس |
| معيّن (Diamond) يطفو وينبض | مكافأة (Shard) |
| عمود ضوء عمودي | Checkpoint / خط النهاية |
| حافة متقطعة (Dashed) | منصة مختفية حاليًا ستعود |

### العناصر وسؤال كل عنصر

| العنصر | السلوك | السؤال الذي يطرحه |
|---|---|---|
| **Block** (منصة ثابتة) | جسم صلب بأي حجم على الـGrid | "هل أستطيع الصعود؟ أين أهبط؟" |
| **Gap** (فجوة) | غياب الأرض + خط موت أسفلها | "متى أبدأ القفزة لأصل؟" |
| **Spikes** (أرضية/سقفية) | صف مثلثات بعدد قابل للضبط، للأعلى أو للأسفل | الأرضية: "متى أقفز؟" · السقفية: "متى **لا** أقفز؟" |
| **Moving Platform** | منصة تتحرك بين نقطتين بحركة ناعمة (Sine) | "متى تكون المنصة في مكانها؟" |
| **Phase Platform** (تختفي) | تظهر لفترة ثم تختفي بدورة ثابتة، ترتعش قبل الاختفاء، وتُرسم متقطعة وهي غائبة | "هل سأصل وهي موجودة؟" (إيقاع) |
| **Saw** (منشار دوّار) | نجمة مسننة تدور، ثابتة أو تتحرك صعودًا/نزولًا أو أفقيًا | "أين أكون عندما يمر؟" (نافذة توقيت) |
| **Shard** | معيّن يطفو، يُجمع باللمس | "هل أخاطر بقفزة مختلفة لأجمعه؟" |
| **Checkpoint** | عمود ضوء يشتعل عند المرور | — |
| **Finish Gate** | بوابة ضوء نهاية المستوى | — |

أي عنصر يمكن أن يتحرك بإضافة مكوّن الحركة نفسه (Composition) — لا نحتاج نوعًا جديدًا لكل تركيبة.

## 8. نظام تصميم المستويات (Level Design System)

### 8.1 الوحدات
- Grid = 64px. كل العناصر تُوضع وتُحجَّم بمضاعفات الـGrid.
- سطح الأرض الأساسي عند `y = 0`. العمق تحت الأرض يُرسم كأعمدة داكنة حتى تبدو الفجوات هاوية.

### 8.2 بنية المستوى: Beats
المستوى = سلسلة **Beats**. كل Beat يدور حول **فكرة واحدة** ويتبع النمط:

```
Introduce (آمن، مع Shards ترسم المسار) → Develop (تكرار أصعب) → Twist (دمج أو عكس) → Rest (أرض آمنة)
```

- **Shards كمعلّم:** أول ظهور لأي عنصر تُوضع فوقه Shards على **قوس القفزة المثالي** — تعلّم اللاعب التوقيت دون نص.
- **Checkpoint** بعد كل Beat رئيسي، ويتبعه دائمًا **≥ 1.5 ثانية أرض آمنة** (لأن اللاعب يعود جاريًا فورًا). هذه القاعدة مُختبرة آليًا.
- **الإيقاع:** المنصات المختفية المتتالية بمسافة قفزة واحدة بينها تُضبط بدورة = زمن قفزتين، وتومض بالتناوب، فتكون كل منصة صلبة لحظة وصول اللاعب ويُقرأ النمط من بعيد.
- **التسامح:** كل قفزة إلزامية في المستويات الأولى يجب أن تقبل نافذة توقيت **≥ 200ms**.
- **مسافة القراءة:** أي عنصر جديد يجب أن يظهر على الشاشة قبل **≥ 1.2 ثانية** من وصول اللاعب إليه.

### 8.3 طريقة إنشاء مستوى جديد
1. Duplicate لمشهد مستوى موجود أو مشهد فارغ من `Level`.
2. سحب عناصر جاهزة (`Block`, `Spikes`, `Saw`...) وضبط الحجم/العدد من الـInspector — الشكل يتحدث مباشرة داخل المحرر.
3. ضبط `LevelData` (الاسم، معامل السرعة).
4. تشغيل اختبار اللعب الآلي للتأكد أن المستوى قابل للإنهاء.

### 8.4 مفاتيح الصعوبة (Difficulty Knobs)
| المفتاح | أمثلة |
|---|---|
| السرعة | معامل سرعة 1.0 → 1.25 عبر المستويات |
| المسافات | فجوات 2 → 5 tiles، عتبات 1 → 2 tiles |
| نافذة التوقيت | منصات أسرع، منصات تختفي بفترات أقصر |
| كثافة الأنماط | مسافة أقل بين الأخطار، راحة أقل |
| الدمج | منصة متحركة + أشواك سقفية، منصات مختفية + منشار |
| القراءة | عناصر تظهر أقرب، مسارات بديلة بمخاطرة أعلى للـShards |

### 8.5 خريطة طريق مستقبلية (مقترح فقط، لا يُنفَّذ الآن)
| المستوى | الفكرة الجديدة |
|---|---|
| 1 | كل الأساسيات بجرعات تعليمية (Prototype) |
| 2 | الإيقاع: منصات مختفية متتالية |
| 3 | المسافات: قفزات طويلة ومنصات عائمة |
| 4 | السقف: ممرات أشواك سقفية ("لا تقفز") |
| 5 | الحركة: مناشير متحركة بأنماط |
| 6+ | دمج فكرتين في كل Beat، ثم رفع السرعة |

## 9. المستوى التجريبي: Level 01 — "Awakening"

الهدف: إثبات جودة الـCore Loop، وعرض كل عناصر §7 بجرعات تعليمية. المدة ≈ 35–45 ثانية بدون موت.

| Beat | الفكرة | المحتوى |
|---|---|---|
| 0 · Runway | البداية | أرض آمنة، "Tap to start"، Shards على الأرض تُجمع بالجري |
| 1 · First Jumps | القفز | فجوة 2 tiles مع Shards على القوس، شوكة واحدة، فجوة 3 tiles، عتبة بارتفاع 1 |
| 2 · Spikes | متى أقفز / متى لا | أشواك 2 ثم 1 ثم 3، ثم **ممر أشواك سقفية** بداخله Shards (مكافأة عدم القفز) |
| ✓ | Checkpoint A | |
| 3 · Heights | الارتفاع | درج صاعد، منصة عائمة فوق هاوية، نزول |
| 4 · Moving | التوقيت | منصة أفقية متحركة فوق هاوية، ثم مصعدان عموديان بطورين مختلفين |
| ✓ | Checkpoint B | |
| 5 · Phase | الإيقاع | سلسلة منصات تختفي بالتناوب فوق هاوية |
| 6 · Saws | نافذة التوقيت | منشار يتحرك عموديًا فوق الأرض، ثم منشار ثابت فوق فجوة (يحدد لحظة القفز) |
| ✓ | Checkpoint C | |
| 7 · Finale | الدمج | منصة متحركة تحت أشواك سقفية، منصات مختفية مع منشار، ثم صعود إلى بوابة النهاية |

التخطيط الدقيق (الإحداثيات) موجود داخل المشهد `levels/level_01.tscn` وهو مصدر الحقيقة.

**النتائج المقاسة (لاعب آلي على الفيزياء الفعلية):** المدة ≈ 35 ثانية، 29 قفزة إلزامية، 32 Shard، 3 Checkpoints.
نافذة التوقيت لكل قفزة بين **283ms** و**480ms+** (الوسيط 433ms) — مستوى أول متسامح. (كان الحد الأدنى 216ms قبل أن يغطي Ledge Assist السقوط على الزوايا.)

## 10. الكاميرا

| الخاصية | السلوك |
|---|---|
| Side Scrolling | الكاميرا تتبع اللاعب أفقيًا بشكل شبه صلب |
| Look Ahead | اللاعب عند ~28% من يسار الشاشة → يرى أكثر من ثلثي الشاشة أمامه |
| Smooth Follow عمودي | الكاميرا تتبع **مستوى الأرض الأخير** وليس كل قفزة → لا تتمايل مع القفزات (مُختبر: 0px تذبذب أثناء قفزة مستوية) |
| السقوط | القفزات ترتفع فقط فوق الأرض، لذا أي نزول تحتها سقوط حقيقي: الكاميرا تتبعه بعد 24px فقط وبسرعة أعلى، وتسمح برؤية 200px تحت خط الموت → موت السقوط يظهر دائمًا داخل الشاشة (مُختبر) |
| انتقالات ناعمة | تنعيم أُسّي (Exponential smoothing) مستقل عن معدل الإطارات |
| Shake | فقط عند الموت: سعة قصوى 7px، تتلاشى خلال ~0.35s |
| عند العودة للـCheckpoint | Fade سريع للأسود يخفي قفزة الكاميرا بدل Pan طويل مزعج |

## 11. Score، Shards، الموت وإعادة البدء

- **Score** = نقاط المسافة (10 نقاط لكل Tile تتقدم فيها) + **100** لكل Shard.
- **Shards:** عددها ظاهر في الـHUD. الـShards المجمّعة **بعد** آخر Checkpoint تعود لمكانها عند الموت.
- **الموت:** تحطم (≈0.45s) → Fade → العودة لآخر Checkpoint → الجري فورًا. الـScore يعود لقيمته عند الـCheckpoint.
- **Restart:** من قائمة الإيقاف أو شاشة النهاية → المستوى من البداية.
- **نهاية المستوى:** البوابة تشتعل، النواة تتوقف، شاشة نتيجة: Score، أفضل Score، Shards (x / المجموع)، زر "Play again".
- **الحفظ:** أفضل Score وأكثر Shards وحالة الإنهاء لكل مستوى، محفوظة محليًا.

## 13. الهوية البصرية

### الألوان
| الدور | اللون |
|---|---|
| السماء (أعلى → أفق) | `#07040A` → `#3A0D18` |
| الشمس/القمر الباهت | `#FFB3AE` مع توهج أحمر |

| الأخطار | أحمر أكثر سطوعًا `#FF3048` مع قلب فاتح ونبض |
| اللاعب | حواف `#FF3D55` + قلب أبيض ساخن `#FFF0F2` |
| Shards | حافة `#FF4D6A` + قلب أبيض وردي |

### الطبقات (من الأبعد للأقرب)
1. تدرج السماء + ضباب الأفق
2. قرص شمس باهت كبير (Parallax شبه ثابت)
3. أبراج ومسلّات هندسية بعيدة (Parallax بطيء)
4. أبراج متوسطة بخطوط Neon رفيعة (Parallax أسرع)
5. طبقة اللعب (منصات، أخطار، اللاعب)
6. جزيئات جمر عائمة خفيفة

### التوهج (Glow)
التوهج يُرسم يدويًا كطبقات خطوط شفافة متدرجة حول الحواف بدل Post-Processing Bloom: أرخص بكثير على الهواتف الضعيفة، ويعمل على كل الأجهزة (Renderer: Compatibility / OpenGL ES 3).

### Particles
قفز، هبوط، شرارات جري، تحطم عند الموت، بريق جمع Shard، اشتعال Checkpoint.

- [ ] هل القفزة تستجيب فورًا عند اللمس؟
- [ ] هل يعرف اللاعب دائمًا لماذا مات؟
- [ ] هل يضغط "مرة ثانية" تلقائيًا بعد الموت؟
- [ ] هل الشخصية مميزة عن الخلفية في كل لحظة؟
- [ ] هل تُقرأ العناصر المتحركة قبل الوصول إليها؟

- [ ] هل الإطارات ثابتة على هاتف متوسط؟
